# 项目改进路线图

> 最后更新：2026-06-03

本文档记录项目当前存在的技术债务和改进方向，按优先级分为 P0（关键）到 P3（扩展）四个等级。

---

## P0 — 关键（影响项目稳定性或可维护性）

### 1. 补充核心模块测试

**现状：** 当前几乎没有测试保护网，所有 API 路由和前端组件均无单元测试或集成测试覆盖。

**目标：** 为核心模块建立测试保护网，确保关键路径的可靠性。

**建议范围：**
- API 路由层：认证鉴权、数据库 CRUD、上传逻辑
- 核心 hooks：`useImagesList`、`useImageActions`、`useDashboard` 等
- 关键工具函数：`formatSize`、`formatDate`、权限校验等
- 支付相关：付费壁纸设置、订单处理

**技术选型建议：** Vitest + React Testing Library（前端）、Supertest（API）

---

### 2. 拆分超大组件 ✅ 已完成

**问题：** 多个组件超过 1000 行，可维护性差。

**完成情况：**

| 组件 | 原始行数 | 拆分文件数 | 主文件行数 |
|------|---------|-----------|-----------|
| DashboardTab | 1,418 行 | 14 个子文件 | ~500 行 |
| Lightbox | 1,289 行 | 9 个子文件 | ~204 行 |
| ImagesTab | 1,820 行 | 13 个子文件 | ~217 行 |

**拆分策略：** 目录 + 子组件模式，原文件保留为重导出（`export { default } from './XxxTab/index'`），外部引用零改动。

---

## P1 — 重要（工程化基础设施）

### 3. 引入统一日志

**现状：** 使用 `console.log` / `console.error` 分散在各处，生产环境无法有效排查问题。

**目标：** 引入结构化日志系统，支持日志级别、上下文信息和日志输出目标配置。

**建议方案：**
- 封装统一 `logger` 工具模块（`lib/logger.ts`）
- 支持 `debug` / `info` / `warn` / `error` 四级
- 生产环境输出到外部服务（如 Axiom、Datadog、自建 ELK）
- 替换现有所有 `console.*` 调用

---

### 4. CI/CD 流水线

**现状：** 无自动化构建和部署流程，依赖手动操作。

**目标：** 建立自动化流水线，确保每次提交经过检查后才部署。

**建议流程：**
```
Push/PR → Lint + Type Check → Build → (Future: Test) → Deploy Preview → Manual → Production
```

**技术选型建议：** GitHub Actions（与代码仓库集成最方便）

**关键步骤：**
- PR 自动触发 `pnpm lint` + `pnpm build`
- 合并到 main 自动部署到生产环境
- 预览环境自动创建（Vercel Preview / Cloudflare Pages）

---

### 5. 迁移管理工具

**现状：** 数据库表结构变更手动执行 SQL，容易遗漏或出错。

**目标：** 引入数据库迁移工具，版本化管理表结构变更。

**建议方案：** 使用 Prisma Migrate 或 Drizzle Kit 管理迁移，或自建轻量迁移脚本（`migrations/` 目录 + 版本号文件）。

---

## P2 — 增强（性能和体验提升）

### 6. Redis 缓存策略

**现状：** Redis 已接入（构建日志可见 Redis connected），但缺少系统化的缓存策略。

**目标：** 为高频读取、低变更的数据添加 Redis 缓存层。

**建议缓存场景：**
- 分类列表（变更频率低，读取频率高）
- 排行榜数据（定时刷新）
- 用户关注统计（短期缓存）
- API 分页结果（短期缓存 + 标签失效）
- 主题专区配置

---

### 7. 暗色模式补齐

**现状：** 部分组件已使用 CSS 变量（如 `var(--color-mute)`），但暗色模式未完整适配。

**目标：** 全站暗色模式可用，所有页面和组件正确显示。

**建议方案：**
- 审计所有硬编码颜色值，替换为 CSS 变量或 Tailwind 暗色类
- 添加 `dark:` 前缀类
- 提供用户切换入口

---

### 8. Bundle 分析 + 虚拟滚动

**现状：** 未进行 Bundle 分析，可能存在未优化的大依赖。长列表（如图片瀑布流）可能导致性能问题。

**目标：**
- Bundle 体积控制在合理范围，识别并优化大依赖
- 长列表使用虚拟滚动，减少 DOM 节点数

**建议工具：**
- `@next/bundle-analyzer` 分析打包体积
- `@tanstack/react-virtual` 或 `react-window` 实现虚拟滚动

---

## P3 — 扩展（产品差异化）

### 9. i18n 国际化

**目标：** 支持多语言，面向国际用户。

**建议方案：** `next-intl` 或 Next.js 内置 i18n，按路由前缀（`/en/`、`/zh/`）区分语言。

---

### 10. PWA 渐进式 Web 应用

**目标：** 支持离线访问、推送通知、添加到主屏幕。

**建议方案：** `@ducanh2912/next-pwa`（Next.js App Router 兼容）。

---

### 11. OG Image 社交分享卡片

**目标：** 在社交媒体分享链接时自动生成精美的预览图。

**建议方案：** Next.js `ImageResponse`（`next/og`），动态生成包含壁纸预览和标题的卡片。
