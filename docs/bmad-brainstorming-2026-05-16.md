## 二、全新发现的欠缺功能

### 🔴 A. 安全与合规（高优先级 — 上一轮几乎未涉及）

#### A1. 注册/登录安全防护 — 验证码与防暴力破解 ✅ 已完成
**现状：** 
- 注册接口 `/api/auth/register` 无任何验证码（CAPTCHA）保护
- 登录接口无失败次数锁定机制
- 忘记密码接口 `/api/auth/forgot-password` 无频率限制，可被滥用枚举邮箱
- rate-limit.ts 仅保护 V1 公开 API，内部 API 无登录/注册级限流
**建议：**
- 注册/登录添加 CAPTCHA（推荐 Altcha — 项目 scripts/ 中已有相关分析脚本）
- 登录失败 5 次后锁定账号 15 分钟
- 忘记密码接口添加 IP 级频率限制（如 5次/小时/IP）
- 敏感操作（修改密码、删除账号）要求二次验证
**已完成：** Altcha 验证码集成（注册/忘记密码）、login-security.ts（登录锁定+IP限流）、中文 strings
**影响：** 极高 — 无防护可被批量注册、暴力破解密码、邮箱枚举  
**工作量：** 中

#### A2. 账号注销与数据删除 ✅ 已完成
**现状：** 代码库中无任何 `delete account`、`账号注销` 相关逻辑。用户无法自助注销账号，不符合《个人信息保护法》/GDPR 要求
**建议：**
- 用户设置中新增「注销账号」功能
- 注销流程：7 天冷静期 → 删除个人信息 → 匿名化用户内容 → 删除关联数据
- 管理后台支持账号封禁/删除
**已完成：** account-deletion.ts（7天冷静期+匿名化）、管理后台封禁/解封、ProfileClient 注销入口、DB迁移
**影响：** 高 — 法律合规必需  
**工作量：** 中

#### A3. CSRF 防护 ✅ 已完成
**现状：** NextAuth.js 的 CSRF token 已内置在表单提交中，但自定义 API（如上传、收藏、举报）未统一验证 CSRF token
**建议：**
- 所有状态变更 API（POST/PUT/PATCH/DELETE）统一校验 NextAuth CSRF token
- 或采用 SameSite Cookie + Origin 检查策略
**已完成：** csrf.ts 服务端验证 + csrf-client.ts 前端注入 + middleware POST/PUT/PATCH/DELETE 统一校验 + 组件 withCsrfHeader 注入
**影响：** 中 — 防止跨站请求伪造攻击  
**工作量：** 小

#### A4. 内容安全审核 — NSFW 自动检测
**现状：** 
- 图片审核完全依赖管理员人工审核（ReviewTab）
- 无任何自动内容安全检测（NSFW/暴力/敏感图片识别）
- 随着内容量增长，纯人工审核将成为瓶颈
**建议：**
- 上传时接入 NSFW 检测 API（如 NSFW.js、Amazon Rekognition、阿里内容安全）
- 自动标记可疑图片，优先进入审核队列
- 管理后台展示自动检测结果（置信度分数）
**影响：** 高 — 内容安全是平台合规的底线  
**工作量：** 中

### 🟡 B. 核心体验缺失（中-高优先级）

#### B1. 暗黑模式
**现状：** 
- `globals.css` 有 `@custom-variant dark` 定义，但代码中未实现主题切换
- 无 ThemeProvider 组件
- 无亮/暗/跟随系统切换入口
- 颜色变量全部硬编码为亮色主题值
**建议：**
- 引入 `next-themes` ThemeProvider
- 定义暗色主题 CSS 变量
- Navbar 添加主题切换按钮
- 尊重 `prefers-color-scheme` 系统偏好
**影响：** 中-高 — 壁纸类应用的核心体验，竞品均支持  
**工作量：** 中

#### B2. 批量上传
**现状：** 
- upload/route.ts 仅处理单文件上传
- UploadClient.tsx 无多文件选择 UI
- task-backlog.md 标记为 P4 但未开发
**建议：**
- 支持多文件拖拽选择（限制数量如 10 张/次）
- 上传进度批量展示（成功/失败/进行中）
- 批量设置共同分类/标签，支持单张微调
**影响：** 高 — 创作者核心需求，单张上传效率极低  
**工作量：** 中

#### B3. 动态壁纸/视频壁纸支持
**现状：** 
- ALLOWED_TYPES 仅 jpeg/png/webp，不支持 mp4/webm
- 无 media_type 字段区分静态/动态壁纸
- 竞品 Wallpaper Engine 以动态壁纸为核心卖点
**建议：**
- 新增 media_type 字段（image/video/live）
- 支持短视频/GIF 壁纸上传和预览
- 视频封面帧自动提取
- 播放控制（循环/暂停）
**影响：** 中 — 差异化功能，但实现成本较高  
**工作量：** 大

#### B4. 邮件服务集成 ✅ 已完成
**现状：** 
- 忘记密码功能只输出重置链接到服务器控制台（DEV 模式）
- 无任何邮件发送服务集成
- 通知系统仅站内通知，无邮件推送
- 管理后台群发通知无邮件渠道
**建议：**
- 接入 Resend/SendGrid/阿里邮件推送
- 支持邮件模板：密码重置、欢迎注册、审核结果、周报等
- 通知设置中增加「邮件通知」选项
**已完成：** 
- email.ts：Resend/SMTP 双模式，数据库优先配置+环境变量回退+5分钟缓存
- 管理后台 SettingsTab：8个邮件配置字段，可直接在界面配置
- 邮件测试功能：test-email API + 管理后台测试按钮
- 邮件模板：密码重置、欢迎注册、审核结果、通用通知
- notification.ts：pushNotification 已集成邮件推送（检查用户偏好）
- 管理后台群发通知：已添加邮件推送（检查邮件配置+用户偏好+5秒超时保护）
**影响：** 高 — 密码重置等关键功能无法在生产环境使用  
**工作量：** 中

### 🟢 C. 平台运营与数据（中优先级）

#### C1. 用户行为分析与运营看板
**现状：** 
- 管理后台 DashboardTab 仅有基础统计（用户数/图片数/下载量）
- 无用户留存率、活跃度、转化漏斗等运营指标
- 无图片热度趋势、分类分布可视化
- 无实时在线用户统计
**建议：**
- 接入轻量分析（PostHog / Umami / 自建）
- 管理后台增加运营看板：
  - DAU/MAU/留存率
  - 下载转化漏斗（浏览→详情→下载）
  - 分类热度排行与趋势
  - 创作者活跃度分布
**影响：** 中 — 运营决策的数据基础  
**工作量：** 中-大

#### C2. 搜索历史与个性化搜索
**现状：** 
- 搜索建议（suggest API）基于全局数据，无个性化
- 无搜索历史记录
- 无热门搜索展示
**建议：**
- 用户搜索历史（前端 localStorage 即可）
- 热门搜索词展示（基于 download_logs/view_logs 聚合）
- 搜索结果按用户偏好排序
**影响：** 中 — 搜索体验提升  
**工作量：** 小-中

#### C3. 数据导出与备份
**现状：** 
- 管理后台无数据导出功能
- 无数据库备份机制
- 用户无法导出自己的数据（上传的图片/收藏/合集）
**建议：**
- 管理后台：CSV 导出用户/图片/下载数据
- 用户端：导出个人数据（GDPR 合规）
- 自动数据库备份（定时任务）
**影响：** 中 — 运营效率 + 合规需求  
**工作量：** 中

#### C4. 操作审计日志增强
**现状：** 
- admin_operation_logs 表存在但功能简单
- 无管理员操作详情记录
- 无可疑操作告警
**建议：**
- 记录所有管理员操作（审核/删除/修改）
- IP 和时间戳记录
- 敏感操作（批量删除、权限变更）告警
- 操作回滚机制
**影响：** 中 — 安全审计和运营追溯  
**工作量：** 小

### 🔵 D. 技术债务与工程质量（中优先级）

#### D1. 测试覆盖
**现状：** 
- 代码库中零测试文件（无 .test.ts/.spec.ts）
- 无 jest/vitest 配置
- 无 E2E 测试
- 功能全靠手动验证
**建议：**
- 引入 Vitest + React Testing Library
- 优先覆盖核心 API 路由（上传/下载/认证）
- 关键组件快照测试
- E2E 测试（Playwright）覆盖核心用户流程
**影响：** 高 — 代码质量和重构信心的基础  
**工作量：** 大（逐步建设）

#### D2. 错误边界与加载状态
**现状：** 
- 无全局 error.tsx 错误边界
- 无 loading.tsx 骨架屏
- 组件错误可能导致整页白屏
- 数据加载无统一 loading 体验
**建议：**
- 每个路由段添加 error.tsx
- 添加 loading.tsx 骨架屏（已有 skeleton.tsx 组件但未使用）
- API 请求统一 loading/error 处理
**影响：** 中 — 用户体验和错误恢复  
**工作量：** 小-中

#### D3. PWA 支持
**现状：** 
- 无 manifest.json
- 无 Service Worker
- 无法添加到手机桌面
- 壁纸类应用的天然 PWA 场景未利用
**建议：**
- 添加 Web App Manifest
- 注册 Service Worker（离线缓存首页）
- 支持添加到主屏幕
- 推送通知（配合壁纸定时更换）
**影响：** 中 — 壁纸应用的原生体验  
**工作量：** 中

#### D4. 图片加载优化
**现状：** 
- 大量使用 `<img>` 标签而非 Next.js `<Image>` 组件
- 无 blur placeholder 预加载
- MinIO 图片无 CDN 加速
- 缩略图可能加载原图分辨率
**建议：**
- 瀑布流使用 blur placeholder + lazy load
- 对接 CDN（Cloudflare/阿里 CDN）
- 利用 image-variants.ts 已有缩略图功能
- 图片格式自动转换（WebP 优先）
**影响：** 中 — 首屏加载速度和带宽成本  
**工作量：** 中

- `/blog` 页面数据硬编码在 page.tsx 中
- 无 CMS 集成，无文章管理后台
- 无法发布/编辑文章
**建议：**
- 接入 Headless CMS（如 Notion、Contentful）
- 或基于 posts 表扩展博客类型
- 支持文章发布/编辑/草稿
**影响：** 低-中 — SEO 和内容营销  
**工作量：** 中

#### E3. Cookie 同意与隐私合规
**现状：** 
- 无 Cookie 同意横幅
- 无隐私偏好管理
- 对 EU 用户不合规
**建议：**
- 添加 Cookie 同意横幅（CMP）

- 隐私设置页面
**影响：** 低-中 — 取决于目标市场  
**工作量：** 小

#### E4. 推荐系统深化
**现状：** 
- recommendations API 基于分类偏好，算法简单
- 无协同过滤
- 无「猜你喜欢」解释
- 无推荐反馈（不感兴趣/减少推荐）
**建议：**
- 基于用户行为的协同过滤
- 推荐理由展示（"因为你收藏了XXX"）
- 用户可反馈推荐质量
- 冷启动用户策略（热门+分类覆盖）
**影响：** 中 — 用户停留时长和发现效率  
**工作量：** 中-大

## 六、关键发现总结

1. **安全是最大短板**：第一轮头脑风暴几乎未涉及安全层面。无验证码、无登录锁定、无CSRF统一防护、无账号注销，这些问题在生产环境中是不可接受的。
2. **邮件服务是关键依赖**：密码重置、通知推送、创作者统计等核心功能都依赖邮件服务，但至今未集成。
3. **暗黑模式不应被遗漏**：壁纸类应用的暗黑模式是用户强需求，CSS 变量已有 dark variant 定义但未实现。
4. **工程质量需补课**：零测试覆盖、无错误边界、无全局 loading 状态，技术债务积累到一定程度会严重影响迭代速度。
5. **批量上传是创作者刚需**：第一轮标记为 P4 但未开发，实际上创作者上传效率是平台内容供给的关键杠杆。
