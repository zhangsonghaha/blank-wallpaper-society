BMAD 第三轮头脑风暴分析于 2026-05-17 完成，报告保存在 `docs/bmad-brainstorming-2026-05-17.md`。

**Why:** 前两轮聚焦功能层面，忽略了代码级安全风险（凭据硬编码）、运维可观测性和数据层问题。

**How to apply:** 
- 最紧急：数据库/MinIO/Redis 凭据必须立即迁移到环境变量
- 关键操作需要数据库事务保护（注册、删除、支付）
- 已有但未集成的功能（NSFW、水印、视频壁纸）需要集成到实际流程
- 限流应迁移到 Redis 以支持水平扩展
- 连接池配置从 3 提升到 10-20

核心发现：
1. 凭据硬编码（db.ts 密码明文）— P0 风险
2. 无数据库事务 — 数据一致性隐患
3. NSFW/水印/视频组件已写但未集成 — 沉没成本
4. 运维可观测性为零（无Sentry/健康检查/结构化日志）
5. 连接池仅3连接 — 并发瓶颈
6. 限流基于内存Map — 不支持多实例
